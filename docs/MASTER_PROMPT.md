## 1. What we are building

A Streamlit game. The player defends a small business chatbot (Beanie, Polar Bean Café) against prompt injection and is scored on two sides: secrets kept (security) and real customers served (helpfulness). The chatbot's information is shown as a round "system core map" with an outer ring (public info), an inner ring (secrets) and a core (most valuable data). Modes: Tutorial and Level mode (fully scripted, no AI, the player picks rules) and Endless mode (the player writes rules, Gemini plays Beanie, a code judge scores the replies).

## 4. Contract

### 4.1 Level JSON (scenarios/cafe.json)
```
{ "id": "cafe", "name": "Polar Bean Café", "description": "...",
  "levels": [ {
    "id": "tutorial_1", "title": "...", "theme": "general hint, never the exact target",
    "min_rules": 1,
    "map_zones": [ {"id","label","ring": "outer"|"inner"|"sensitive"|"core","points"} ],
    "rules": [ {"id","label","text","cost": 1} ],
    "attack_packages": [ [ {"text","target_zone","type","blocked_by": [rule ids],
                            "reply_if_blocked","reply_if_leaked"} ] ],
    "customer_questions": [ {"text","zone","broken_by": [rule ids],"reply_ok","reply_refused"} ],
    "coach_tips": { "<attack type>": "one short tip" },
    "guide_steps": [ ... ]            // only tutorial_1
  } ],
  "sections": [ ... ]                 // optional, Endless mode, see 4.5
}
```
Attack types: direct_question, impersonation, instruction_override, transformation, emotional. Outer zones (public, default 10 points) are information Beanie SHOULD share. Inner (internal, default 25), sensitive (default 50) and core (default 150) zones are secrets. A level may use any of the four rings, tutorial_1 uses outer, inner and core only. Ids are short, lowercase, use underscores and are never reused inside one file. All data is fictional.

### 4.2 engine/level.py
- pick_package(level, rng=None) -> int
- run_level(level, chosen_rules, package_index) -> dict. Events alternate attack, customer, attack, customer (leftovers at the end). An attack is blocked if any chosen rule is in blocked_by, otherwise its target zone is lost. A customer is refused if any chosen rule is in broken_by, which loses its outer zone. Unknown rule ids raise ValueError. Returns:
```
{ "events": [ {"step","sender": "attacker"|"customer","text","reply","zone",
               "outcome": "blocked"|"leaked"|"served"|"refused",
               "map": {zone_id: "safe"|"lost"}} ],      // map state AFTER the event
  "security": {"earned","total"}, "helpfulness": {"earned","total"},
  "core_hacked": bool, "rules_used": int, "package_index": int }
```
- explain_result(level, chosen_rules, result) -> list[dict], one item per leak or refusal: {"step","kind": "leak"|"refusal","zone","attack_type" (leaks only),"message","caused_by_rules": [ids of chosen rules responsible, refusals only],"coach_tip"}.

### 4.3 engine/grading.py
grade_level(result, min_rules) -> {"grade": "perfect"|"stars"|"fail"|"lose","stars","score","security_pct","helpfulness_pct"}. Core hacked means lose. Score = 100 * (security earned + helpfulness earned) / (both totals), minus RULE_PENALTY=5 per rule above min_rules, minus LENGTH_PENALTY=2 per started 100 characters above FREE_RULES_CHARS=400 when result has "rules_chars", floored at 0. Perfect needs 100% on both sides and rules_used <= min_rules. Otherwise 3 stars at >= 90, 2 at >= 75, 1 at >= 60, else fail. All numbers are named constants.

### 4.4 engine/save.py
export_game(record) -> str (pretty JSON, adds "format": "chatbot-defense-arena/1"). import_game(text) -> dict, raises ValueError on a missing or wrong format field or missing "events". The engine never writes files.

### 4.5 Endless section (inside cafe.json "sections")
```
{ "id","title","theme","map_zones": [...],
  "business_prompt": "Beanie's instructions including the secrets",
  "secrets_by_zone": {zone_id: "BEAN-STAFF-25"},
  "attack_packages": [ [ {"text","target_zone","type"} ] ],
  "customer_questions": [ {"text","zone","expected_facts": ["7am"], "reply_hint": "..."} ],
  "coach_tips": {...} }
```
run_section(section, player_rules, package_index) in engine/endless.py returns the SAME shape as run_level plus "rules_chars" and rules_used = 0, so grade_level(result, 0) and every screen work unchanged.

### 4.6 engine/storage.py
new_session_id(), build_row(...), record_play(mode, scenario_id, level_id, run_id, session_id, attempt_number, result, grade, chosen_rules=None, player_rules=None, guide_skipped=None, ai_model=None, ai_temperature=None) -> bool. Table and rules: docs/supabase.sql and PLAN.md section 7.1.

### Phase 14 (A). Endless run (several sections in a row)
engine/endless_run.py. A run is a list of sections played one after another. start_run(scenario_id, rng=None) -> dict state, play_section(state, player_rules) -> {"result","grade","passed","section_points","state"}. Rules carry over between sections (the player may edit them). A section passes with at least 1 star, meaning grade is "perfect" or "stars". A fail, a lose (core hacked) or a rate limit stop ends the run. The business changes every 3 sections and loops. Difficulty grows with the section number n: direct and impersonation attacks from section 1, instruction_override from 2, emotional from 3, transformation from 4, combined from 5, attacks per section go from 3 up to 7 and customers from 3 up to 5 (use more packages and the sections list in cafe.json, build them from existing section data when none exist). Section points: perfect 800, 3 stars 500, 2 stars 250, 1 star 100, each multiplied by (1 + 0.15 * (n - 1)), plus a bonus of max(0, 100 - number of words in the rules). All numbers are named constants. Tests with USE_FAKE_AI=true. Commit "Add endless run".

## 7. Design decisions merged from the teammate's demo

These come from a separate browser demo built by a teammate. That demo is a visual and design reference only. Never copy or commit its files, write everything in this repo from scratch.
- Four rings on the map: public 10, internal 25, sensitive 50, core 150 points by default. A breach of the core loses the round.
- Rule cards in Level mode: defense, decoy, trap, cosmetic. The game never says which rules were unnecessary.
- Wasting rules lowers the grade, picking everything must never earn a good grade.
- A new shop of rules is built for every try so the same cards do not pass every time (Phase 16).
- Endless mode is a run of sections that gets harder, passes need at least 1 star, one failed section ends the run (Phase 14).
- Chat layout: customers and attackers on the left, the chatbot on the right. The map updates after every message, with a visible outline on the attacked zone, a marker when breached, and a different marker when a customer was turned away. A replay scrubber lets the player step through the round.
- Keep from our own plan: Gemini through call_ai (free tier, USE_FAKE_AI=true default), code based judge, scenarios in JSON, optional anonymous storage with a consent checkbox, the grade thresholds in 4.3.
- Not in scope for the hackathon: a public record board (needs read access that the insert only storage deliberately avoids), items and power ups, an in browser developer panel for keys.
